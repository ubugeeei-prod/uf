## What you need first

A project that runs — [Your first project](/guide/project) makes one. The
[tutorial](/guide/tutorial) builds one application out of most of the pages
below, and is the quickest way to see how they fit before reading any of them in
detail.

## The pages, in order

<SectionContents section="Build an app" />

The order is what most applications need first. [Routing](/guide/routing) leads
because a route is what the rest attaches to: a loader, a layout, a Suspense
boundary, a form that posts to an action. Then the server boundary —
[Server Components](/guide/server-components) and
[Server actions](/guide/server-actions) — and the data, input, forms and state
that cross it; then what the interface looks like and how its controls behave.
After those come the pages you reach for once the core works:
[Rendering modes](/guide/rendering) and [Answering requests](/guide/routing/requests)
for what each route becomes and what answers it, Suspense and transitions,
assets and caching, signing in, typed effects, GraphQL, and last what a deployed
application needs around it — logs and measurements. The syntax every example is
written in is [Flow, the modern parts](/guide/flow), in Start.

## When you are done

[Targets](/guide/targets) is where an application goes once it builds: a server
or a static host, a single executable file, a phone, a terminal.
[Testing](/guide/testing) is in [The toolchain](/guide/toolchain), with the other
commands you run against what you built.
