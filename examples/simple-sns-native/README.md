# Commonplace Native

[Commonplace](../simple-sns-graphql) on Expo: the web examples' screens, members, notes and
visual language, using Flow components, the typed @uniflowed/stylex/native entry, file routes,
React Navigation stacks and tabs, bundled images, and the real native test renderer.

| Web | Here |
| --- | --- |
| Feed: channels, search, composer, reactions | The Feed tab; channel and search are the screen's state rather than the URL |
| A note in the feed | Also its own screen, pushed over the tabs |
| Clips: a vertical player | The Clips tab, one clip to a screen: edge to edge under the status bar, paged vertically, with a dark tab bar. The same clips as posters that link to their source — no video dependency |
| Inbox: thread list beside the conversation | The Inbox tab lists threads; a conversation is pushed over the tabs |
| Settings | The Settings tab, with sign out |
| Signup and login | One Join screen without a password: there is no service to check one against |

The ink, muted and rule colours, 6 px corners, hairline rules between rows and the 32 px
heading are the web stylesheet's. The navigation icons are drawn from views, because the web's
are SVG paths and this app adds no SVG dependency.

From this directory, with uf alpha.41 or later:

```sh
uf install
uf dev --target ios
# Or: uf dev --target android
uf check
uf test
uf build --target ios
uf build --target android
```

Open the Expo project in a simulator or a device with a compatible Expo client.
Metro is configured through the public withUniflowedMetro adapter; the application
supplies its own React Navigation navigator factories. React, screens and safe-area
context follow the pinned Expo SDK's compatibility matrix; CI runs Expo's offline
dependency check before the native tests and bundles. Node 24 or later is needed.
The example copies its local uf dependencies during installation so their native
peers resolve from this app. Run npm ci again after editing those uf packages.

The flow-typed declarations describe the two no-config React Navigation factories
used here. React Navigation's TypeScript state-bag constraints assume mutable-array
covariance; the app uses this narrow Flow boundary and uf's generated route types.
Other React Navigation exports need their own declarations when added to the app.

The four tabs live in app/(tabs), each screen beside the components only it uses; a note, a
conversation and Join each own a route outside the tabs, so they cover the tab bar. The model
(social.js), the service, its React client, the styles, the shared components and the media live
in app/_shared. app/commonplace.test.js drives the whole app through a service it hands in: one
that answers at once, or one that holds a call open or refuses it, which is how the skeleton, an
optimistic reaction going back, a note in the list before the service has it, and a failed read
recovering are each asserted rather than hoped for. The router and router.native.js files are generated by uf, not
hand-maintained.

app/_shared/service.js is the web examples' service in memory: the same four members and notes,
reactions per account, two private threads, and the account's settings. It knows nothing about
React, and every call is a promise that takes a moment (350 ms), because that is what the
screens have to be written for. It resets when the app restarts. This example demonstrates the
native interface; the separate simple-sns-graphql example owns a real Go backend and BFF. No
ORM, schema migration tool or server runtime is embedded in this app.

## Async React

The screens are written the way the web examples' are, with React 19's own pieces and no
data library.

- **Reads suspend.** `useResource` (app/_shared/client.js) hands a screen a promise for this
  revision of the data, and `AsyncRegion` reads it with `use` beneath a Suspense boundary whose
  fallback is a skeleton of that region. The heading, tabs and search are on screen at once; only
  the notes wait. A read that fails is data, not a thrown error: the region says so and offers
  `Try again`, and the rest of the screen is untouched.
- **Writes are Actions.** Publishing, reacting, sending, saving, joining and signing out each run
  through `useActionState`, so the button says `Publishing…` and cannot be pressed twice, and
  what the Action returned — a `FormState` — is matched into an alert or a confirmation.
- **The answer is shown before it is known.** A reaction, a note being published and a message
  being sent use `useOptimistic`: the heart fills, the note is in the list marked
  `Publishing…`, the bubble is in the log marked `Sending…`. If the service refuses, the
  optimistic value is dropped and the screen is as it was, with the reason under it.
- **A write refreshes by revision, in a transition.** A successful Action bumps one number;
  every read is keyed by it, so every screen asks again. Because the bump is a transition, what
  is on screen stays until the new answers are in, and the optimistic value holds until then —
  a note never appears twice and a heart never flickers back.
- **Changing channel or search is a transition too.** The notes already shown stay, dimmed; no
  skeleton returns. The tab itself moves at once, through `useOptimistic`, because what the
  person pressed is not something to wait for.

Reads are cached outside React, in the provider. A component that suspends before it has
mounted keeps no state or memo, so a promise it created itself would be created again on every
attempt and never be the one that resolved.

## Flow

- `match` wherever a value has cases: a `Session` is a guest or an account, a read is
  `ready` or `failed`, a `FormState` is idle, a success or an error, a conversation is
  unauthenticated, missing or ready — and a topic, a tab and a glyph are each one of a closed
  set. None of them is an `if` ladder that a new case could slip past.
- `renders` where a component promises what it draws: `SignInPrompt renders EmptyState`,
  `Avatar renders AvatarFrame`, `FormStatus renders? Feedback`. `renders?` for an optional
  slot — `EmptyState`'s `action` is an `ActionLink` or a `Button` or nothing — and `renders*` for
  lists that accept only their own rows: `PostList` takes `PostCard`s, `ThreadList`
  `ThreadLink`s, `MessageLog` `MessageBubble`s, `TabStrip` `ChannelTab`s.
- `hook` syntax for `useSocial` and `useResource`, and component syntax throughout.

Two boundaries are explicit rather than hidden. app/_shared/media.js is the one place an
imported image becomes an `Image` source: Metro resolves it to an asset, while uf's asset
declarations describe the web's URL string. And StyleX native compiles a subset of React
Native's style properties; a link's underline and a multiline input's top alignment are outside
it, and are passed beside the compiled style as plain React Native styles. `Image` and
`TextInput` take styles declared in their own module, because Flow's check of those two
components runs out of recursion on a style imported from another.

Portraits and clip posters keep their own licenses; see app/_shared/media/CREDITS.md.

CI installs packed uf packages outside the workspace, runs the native interaction
tests and produces iOS and Android Metro bundles. This is not a physical-device test, and
nothing in it looks at a rendered screen.
